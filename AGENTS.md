# Работа с репозиторием

## Назначение и структура

`micro` — общий Python-пакет для микросервисов: FastAPI, Kafka, PostgreSQL,
модели событий и интеграции с внешними сервисами. Требуется Python >= 3.11.
Сборка через setuptools; версия и основные зависимости находятся в `pyproject.toml`.

- `src/micro/` — исходный код пакета; правки вносить здесь.
- `src/micro/models/` — Pydantic-модели событий.
- `tests/` — тесты pytest и вспомогательные примеры.
- `docs/ru/` — AsyncAPI-описания и дополнительная документация.
- `README.md` — описание, настройка и примеры использования.
- `changelog.md` в корне — история изменений. `src/micro/changelog.md` сейчас пуст.
- `build/`, `dist/` — результаты сборки; не редактировать вручную.

## Разработка

- Сохранять асинхронный интерфейс ввода-вывода и стиль соседнего кода.
- Использовать `logging.getLogger(__name__)`, SQL-параметры передавать отдельно
  от текста запроса.
- Общую конфигурацию читать через `micro.config`; новые переменные описывать
  в README. Не добавлять реальные токены, пароли и файлы `.env` в Git.
- События наследуются от `HeaderEvent`; имя класса используется как тип сообщения.
  Не менять существующие имена и поля без учёта совместимости потребителей.
- `Schema` кэширует модели из загруженных модулей `micro.models.*`.
  При добавлении нового модуля проверить его импорт до первого получения схем.
- `DB.transaction()` и `defer_kafka()` привязаны к текущей asyncio-задаче;
  нельзя использовать их унаследованный контекст в дочерних задачах.
- Описывать изменения по-русски; changelog пополнять по фактическому diff,
  без выдуманных релизов и повышения версии без запроса.

## Установка и проверки

```bash
python3 -m venv venv
. venv/bin/activate
python -m pip install -e .
python -m pip install pytest pytest-asyncio dictdiffer
python -m pytest tests/test_events.py tests/test_single.py tests/test_diff.py
git diff --check
```

Часть импортируемых зависимостей не объявлена в `pyproject.toml`:
см. таблицу дополнительных пакетов в README. Для тестов выше внешние Kafka
и PostgreSQL не требуются. Полноценный запуск сервиса требует зависимостей,
конфигурации и соответствующей инфраструктуры. Не запускать интеграции
и миграции с рабочими учётными данными ради проверки документации.

Готовых настроек линтера и форматтера в репозитории нет. CI при push в `master`
выполняет обновление удалённого checkout через SSH; автоматического запуска
тестов в текущем workflow нет.
