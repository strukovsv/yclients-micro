## 04.11.2026

Не выпущено.

### Добавлено

- Общее cron-событие `OutboxFlush` для доставки собственных outbox-очередей
  подписанных сервисов. `WorkerOutboxFlush` сохранено для совместимости.
- `DB.connection()` и `DB.transaction()` для работы на одном соединении
  PostgreSQL в текущей asyncio-задаче. Вложенные транзакции создают savepoint;
  контекст соединения восстанавливается при выходе. Использование соединения
  транзакции из другой задачи вызывает `RuntimeError`.
- Контекст `defer_kafka(sender)` для передачи готовых Kafka-сообщений
  асинхронной функции сохранения в outbox приложения. Функция получает
  `topic`, строковый ключ (либо `None`) и `value`; контекст восстанавливается
  при выходе. Отправка из другой задачи с унаследованным контекстом запрещена.
- Модель cron-события `WorkerOutboxFlush` для запроса повторной доставки
  outbox сервиса worker, наследующая обязательное поле `data` от `CronBaseClass`.
- README с описанием модулей, установки, конфигурации, HTTP-маршрутов,
  обработки событий, транзакций и использования перехвата отправки для outbox.
- `AGENTS.md` с инструкциями по работе с репозиторием.

### Изменено

- `DB.execute()`, `DB.returning()` и `DB.fetchall()` используют общий
  `connection()`, чтобы участвовать в активной транзакции текущей задачи.
  `fetchone()` использует это соединение через `fetchall()`.

### Исправлено

- При ошибке или отмене запуска Kafka producer его ссылка сбрасывается,
  выполняется попытка закрытия созданного producer, а исходное исключение
  передаётся вызывающему коду. Следующая отправка может повторить запуск.
